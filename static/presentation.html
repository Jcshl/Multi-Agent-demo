01项目做什么

用户一句话可能混合「查攻略」「查玩家 UID 数据」或纯闲聊。单一对话机器人容易串意图或编造数据库字段。 本项目用编排器先判定意图，再交给对应专家 Agent；同一轮里两类需求并存时，走复合流程并行处理后合并回答。

  • 攻略专家：多轮工具循环（RAG 检索、安全计算等），面向游戏机制与养成问答。
  • 账号专家：只读 MySQL 工具链，按 UID / 关键词查库，避免 LLM 凭空生成表格数据。
  • 闲聊专家：无业务工具，承担寒暄与非任务对话。

02分层架构

三种入口（CLI / Streamlit / FastAPI）共用同一 MultiAgentOrchestrator.chat()。 编排层负责意图路由（LLM JSON + 启发式纠偏）、composite 拆问与合并、会话链 _stm_chain、可选指代消解与全局轮次注入。 返回给用户时：单一意图为对应专家的一段 reply；composite 会先有攻略与账号两段子回复，再经合并 LLM 合成一段正文。 结束会话或「新对话」时，提纲摘要写入 SQLite 长期保存，新会话初始化时可召回注入各 Agent。 Web 端 static/index.html 用 localStorage 持久化多会话聊天记录。

03意图路由

默认由 LLM 输出 JSON 意图（game / account / casual / composite），失败则回退启发式。 编排器对常见误判做纠偏（例如纯算术统一走 game 以使用 calculator；「攻略 + 上文 UID」抬升为 composite）。 环境变量 MULTI_AGENT_ROUTE_MODE 可切换 llm / heuristic / 固定单一路由便于调试。

单一意图

命中后调用对应专家；各 Agent 自带多轮上下文，并可注入 SQLite 提纲摘要。

composite

LLM 拆成 game_query / account_query，攻略与账号并行，再由合并 LLM 输出一段回复。

04复合问题（并行 + 合并）

拆分失败时可用正则抽取 UID 等规则回退，避免整条链路失败。

05技术栈

模型通过 OpenAI 兼容接口对接（如 SiliconFlow）；向量检索本地落盘，便于离线演示。

06如何运行

  • CLI：python main.py
  • 网页对话（本页同源）：uvicorn api_app:app --host 0.0.0.0 --port 8000 后访问首页或本展示页
  • Streamlit：streamlit run streamlit_app.py

环境变量需配置 MODEL_NAME、SILICONFLOW_API_KEY；RAG 与 MySQL 详见仓库内 .env.example。
